================================================================================
PROJECT MANAGEMENT APPLICATION — COMPLETE ARCHITECTURE SUMMARY
================================================================================

OVERVIEW
--------
A desktop Project Management Application built with Python + Tkinter.
Data is stored in a single Excel file (project_data.xlsx) with multiple sheets.
The app reads/writes directly to Excel using pandas + openpyxl.
No database. No web server. Fully offline desktop app.

Entry point : main.py
Data file   : input/project_data.xlsx
Window size : 1200x700 (min 900x600)

================================================================================
EXCEL DATA STRUCTURE  (input/project_data.xlsx)
================================================================================

Sheet 1 — Projects
  Columns: ProjectID, ProjectName, (other project-level fields)
  Primary key: ProjectID

Sheet 2 — Tasks
  Columns: TaskID, ProjectID, ProjectName, TaskName, ParentTaskID,
           AssignedTo, StartDate, EndDate, Status, Progress
  Primary key: TaskID
  Foreign keys: ProjectID → Projects.ProjectID
                ParentTaskID → Tasks.TaskID (self-referential, nullable)
  Hierarchy: unlimited depth parent-child via ParentTaskID

Sheet 3 — ProjectStatus
  Columns: ProjectID, ProjectName, Progress, AutoStatus, LastUpdated
  Auto-computed — written by data_service.update_project_metrics()
  AutoStatus values: "Green" | "Amber" | "Red"

================================================================================
MODULE DETAILS
================================================================================

--- config/settings.py ---
  Class: Settings
  - BASE_DIR       : project root (resolved from file path)
  - INPUT_FOLDER   : BASE_DIR/input
  - EXCEL_FILE     : INPUT_FOLDER/project_data.xlsx
  - SHEETS dict    : {"projects":"Projects","tasks":"Tasks","status":"ProjectStatus"}


--- repository/excel_repository.py ---
  Class: ExcelRepository
  All methods read fresh from disk every call (no in-memory cache).

  get_all_sheets()                          → list of sheet names
  read_sheet(sheet_name)                    → pd.DataFrame
  get_columns(sheet_name)                   → list of column names
  write_sheet(sheet_name, df)               → overwrites sheet in Excel
  append_row(sheet_name, row_data)          → reads + appends + writes
  update_row_by_id(sheet, key_col, key_val, updated_data) → updates matching row
  delete_row(sheet_name, row_index)         → drops row by index + writes


--- core/task_hierarchy.py ---
  Class: TaskHierarchyBuilder
  build_tree(tasks) → list of root task dicts, each with "children" list
  - Cleans TaskID/ParentTaskID to int via safe_int()
  - Builds task_map {id: task}, then links children to parents
  - Returns only root nodes (ParentTaskID is None or invalid)
  - Each node dict has a "children" key with nested child nodes


--- core/hierarchy_validator.py ---
  Class: HierarchyValidator
  validate(tasks) → raises ValueError on any violation
  - Checks ParentTaskID exists in task set
  - Checks task is not its own parent
  - Calls check_circular() to detect cycles
  check_circular(tasks) → raises ValueError if cycle detected
  - Builds parent_map {task_id: parent_id}
  - Walks up the chain for each task, detects revisited nodes


--- core/schema_reader.py ---
  Class: SchemaReader
  get_schema()                → dict of all sheets with columns + dtypes
  get_sheet_schema(sheet)     → dict with columns + dtypes for one sheet


--- core/excel_watcher.py ---
  Class: ExcelWatcher + ExcelChangeHandler
  - Uses watchdog library to monitor INPUT_FOLDER
  - On project_data.xlsx modification → fires callback after 500ms debounce
  - MainWindow.on_excel_changed() → root.after(0, _refresh_all)
  - _refresh_all() refreshes current_table and timeline if open


--- services/data_service.py ---
  Class: DataService  (main orchestrator)

  Basic passthrough methods:
    get_sheets(), get_schema(), get_sheet_data(sheet), get_columns(sheet)
    add_row(sheet, row_data), update_row(sheet, idx, data)
    update_row_by_id(sheet, key_col, key_val, data), delete_row(sheet, idx)

  Dynamic sheet detection:
    get_task_sheet()          → finds sheet with TaskID + ProjectID columns
    get_project_status_sheet()→ finds sheet with ProjectID + Progress + AutoStatus

  Task ID generation:
    generate_task_id()        → max(TaskID) + 1, safe against NaN

  Main engine:
    update_project_metrics(project_id)
      1. Loads all tasks, filters by project_id
      2. Calls ProgressService.calculate_task_progress() — recursive avg
      3. Merges updated Progress back into full task dataset
      4. Writes full Tasks sheet back to Excel
      5. Calls ProgressService.calculate_project_progress() — avg of roots
      6. Calls ProjectStatusService.calculate_status() → Green/Amber/Red
      7. Updates or inserts row in ProjectStatus sheet

  get_hierarchy_ordered_tasks()
      - Used by TimelineView only
      - Merges ProjectName, groups by project, fixes invalid parents,
        builds tree via TaskHierarchyBuilder, flattens with level numbers
      - Returns flat list with is_project=True rows as project headers


--- services/progress_service.py ---
  Class: ProgressService
  calculate_task_progress(tasks)
    - Builds task_map and children_map
    - Recursive compute(task_id):
        leaf node  → returns its own Progress float
        parent node → returns average of children's computed progress
    - Runs compute() for all root tasks (ParentTaskID is None)
    - Returns modified tasks list with updated Progress values

  calculate_project_progress(tasks)
    - Averages Progress of root tasks only
    - Returns float (0.0 if no roots)


--- services/project_status_service.py ---
  Class: ProjectStatusService
  calculate_status(tasks) → "Green" | "Amber" | "Red"
    - Counts tasks where EndDate < today AND Progress < 100 (delayed)
    - delayed > 30% of total → "Red"
    - delayed > 0            → "Amber"
    - otherwise              → "Green"

UI MODULE DETAILS
================================================================================

--- ui/main_window.py ---
  Class: MainWindow
  Layout:
    root (tk.Tk, 1200x700)
    ├── sidebar (130px wide, dark #161B27)
    │     └── sheet buttons (one per Excel sheet, clickable)
    └── main_area (expands to fill)
          ├── title_bar (48px, shows current sheet name + Timeline button)
          ├── content_frame (fills remaining space)
          │     └── DynamicTable (current sheet's table)
          └── timeline_overlay (placed over content_frame when Timeline open)

  Sheet switching: load_sheet(sheet_name)
    - Destroys current DynamicTable, creates new one for selected sheet
    - Shows/hides Timeline button (only for Tasks sheet)

  Timeline toggle: _toggle_timeline()
    - Opens TimelineView inside timeline_overlay using place(relwidth=1, relheight=1)
    - Wires on_data_changed callback to refresh task table after drag-drop
    - Closes by place_forget()

  Excel watcher: start_watcher()
    - Starts ExcelWatcher on app launch
    - On file change → refreshes current table + timeline
    - Stopped cleanly on window close


--- ui/dynamic_table.py ---
  Class: DynamicTable (ttk.Frame)
  The main data table. Handles all CRUD for all sheets.

  Theme: MS-Project / Excel style
    - Dark blue header (#1F4E79), white/light-blue alternating rows
    - Bold project header rows (dark blue #2B5F8E)
    - Bold parent task rows (light blue #E8F0FB)
    - Color tags: green/amber/red for ProjectStatus rows

  Tasks sheet specifics:
    - show="tree headings" — hierarchical tree column (#0) + data columns
    - Tree column shows row number + indented task name
    - ProjectName merged from Projects sheet on load
    - Tasks grouped under project header rows (not stored, visual only)
    - Hierarchy built by TaskHierarchyBuilder, inserted recursively

  Non-Tasks sheets:
    - show="headings" — flat table, all columns stretch to fill width

  Toolbar buttons: Add | Subtask | Edit | Delete | Refresh | Recalculate

  CRUD operations:
    add_record()
      - Opens DynamicForm excluding TaskID and ParentTaskID
      - Generates new TaskID via data_service.generate_task_id()
      - Sets ParentTaskID=None (root task)
      - Validates with HierarchyValidator before saving
      - Calls update_project_metrics() after save

    add_subtask()
      - Requires a task row to be selected (not project header)
      - Reads parent TaskID and ProjectID from selected row
      - Opens DynamicForm excluding TaskID, ProjectID, ParentTaskID
      - Sets ParentTaskID = selected task's TaskID
      - Sets ProjectID = selected task's ProjectID
      - Validates with HierarchyValidator before saving

    edit_record()
      - Opens DynamicForm pre-filled with existing values
      - For Tasks: preserves TaskID, ParentTaskID, ProjectID (not editable)
      - Validates with HierarchyValidator before saving
      - Uses repo.write_sheet() directly for Tasks

    delete_record()
      - For Tasks: removes by TaskID, orphans children (they become roots)
      - For other sheets: removes by row index
      - Confirms with messagebox before deleting

    _do_reparent(src_task_id, src_project_id, new_parent_id, new_project_id, ...)
      - Shared by drag-drop and assign-parent dialog
      - Updates both ParentTaskID AND ProjectID in Tasks sheet
      - Validates before writing
      - Updates metrics for both old and new project

  Drag-and-drop (Tasks only):
    - ButtonPress-1 → _on_drag_start (stores source item)
    - B1-Motion     → _on_drag_motion (shows tooltip, highlights target)
    - ButtonRelease → _on_drag_release (confirms move, calls _do_reparent)
    - Project header rows cannot be dragged
    - Drag tooltip shows task name near cursor

  Right-click context menu (Tasks only):
    Edit | Add Subtask | Assign/Change Parent | Delete

  Assign Parent dialog (_ParentPickerDialog):
    - Lists all other tasks as candidates
    - Search box to filter by name or ID
    - "Make Root Task" button to remove parent
    - On confirm → calls _do_reparent()

  Column sorting: click heading → toggles asc/desc, shows ▲/▼ arrow

  Scrollbars: grid layout (tree + vsb + hsb) so tree fills all space


--- ui/dynamic_form.py ---
  Class: DynamicForm (tk.Toplevel, modal)
  Auto-generates form fields based on column list passed in.

  Field types by column name:
    ParentTaskID  → Combobox (readonly), populated with "ID - TaskName" options
    Status        → Combobox: Not Started / In Progress / Completed / Blocked
    AssignedTo    → Combobox: hardcoded team member names
    Progress      → Combobox: 0,10,20,...,100
    *date*        → DateEntry (tkcalendar), format yyyy-mm-dd
    anything else → plain ttk.Entry

  submit():
    - Parses ParentTaskID from "15 - TaskName" format → int
    - Parses Progress → float
    - Prevents self-parent (TaskID == ParentTaskID)
    - Calls submit_callback(data) then destroys form


--- ui/toolbar.py ---
  Class: CommandToolbar (ttk.Frame)
  Buttons: Add | Subtask | Edit | Delete | Refresh | Recalculate (optional)
  Each button calls the callback passed in from DynamicTable


--- ui/timeline_view.py ---
  Class: TimelineView (tk.Frame)
  A full Gantt chart rendered on a tk.Canvas.

  Constants:
    ROW_H=36, HEADER_H=60, DAY_W=24 (default zoom), LEFT_W=260

  Data loading:
    load_data() → calls data_service.get_hierarchy_ordered_tasks()
    Parses StartDate/EndDate to datetime objects (_start, _end)
    Computes project_start/project_end from min/max dates

  Drawing pipeline (draw()):
    _draw_background() → fills canvas
    _draw_header()     → month labels (top), day numbers (bottom), weekend shading
    _draw_rows()       → iterates visible tasks, draws row bg + grid lines
    _draw_task_label() → left panel: arrow/dot, task name, progress pill badge
    _draw_bar()        → Gantt bar with shadow, progress overlay, resize handle
    _draw_today_line() → orange dashed vertical line + TODAY label

  Collapse/expand:
    Projects: click ▶/▼ arrow → _toggle_project(proj_name)
              stores collapsed project names in collapsed_projects set
    Tasks:    click ▶/▼ arrow → _toggle_task(task_id)
              stores collapsed task IDs in collapsed_tasks set
              _get_visible_tasks() skips children of collapsed tasks
              using level-based ancestor tracking

  Bar colours (_smart_colour):
    Completed/Done/Closed → green
    EndDate < today       → red  (overdue)
    EndDate within 3 days → amber (at risk)
    In Progress/Active    → blue
    Not Started/Pending   → gray
    fallback              → purple

  Drag-and-drop on bars:
    Left handle  (10px) → resize_start mode
    Right handle (10px) → resize_end mode
    Middle of bar       → move mode (keeps duration)
    On drop → _save_task_dates() → repo.update_row_by_id()
    Fires on_data_changed callback → MainWindow refreshes task table

  Zoom: +4/-4 px per day, range 8–60px
  Scroll: mousewheel (vertical), Shift+mousewheel (horizontal)
  Toolbar buttons: ← → scroll, + - zoom, ↺ Today
  Tooltip: hover over task row → shows name, dates, duration, status, progress, owner


================================================================================
DATA FLOW — ADD SUBTASK EXAMPLE
================================================================================

1. User selects a task row in DynamicTable
2. Clicks "Subtask" toolbar button → add_subtask()
3. Reads parent TaskID and ProjectID from selected row values
4. Opens DynamicForm (modal) with form_columns (no TaskID/ProjectID/ParentTaskID)
5. User fills form, clicks Save → DynamicForm.submit() → save(data) callback
6. save() calls clean_data(data) to normalize NaN/None/Progress
7. Generates new TaskID via data_service.generate_task_id()
8. Sets data["ParentTaskID"] = parent task's TaskID (int)
9. Sets data["ProjectID"] = parent task's ProjectID
10. Loads current Tasks sheet, appends new task to list
11. HierarchyValidator.validate() checks for invalid parent / circular refs
12. data_service.add_row("Tasks", data) → ExcelRepository.append_row()
13. data_service.update_project_metrics(project_id) recalculates progress+status
14. DynamicTable.refresh() clears tree and reloads from Excel


================================================================================
DATA FLOW — TIMELINE DRAG-DROP EXAMPLE
================================================================================

1. User clicks on a Gantt bar → _on_click() detects bar hit, sets drag_task
2. User drags → _on_drag_motion() → _do_drag() updates task._start/_end in memory
3. Amber outline drawn around new bar position while dragging
4. User releases → _on_drop() → _save_task_dates(task, new_start, new_end)
5. Calls repo.update_row_by_id("Tasks", "TaskID", task_id, {StartDate, EndDate})
6. Updates task dict in memory to keep timeline in sync
7. Fires on_data_changed() → MainWindow._on_timeline_data_changed()
8. DynamicTable.refresh() reloads task table with new dates


================================================================================
KEY DESIGN DECISIONS
================================================================================

1. No in-memory cache — every read hits Excel directly. Simple but slower.

2. HierarchyValidator runs before every write that touches Tasks.
   Prevents: self-parent, invalid ParentTaskID, circular references.

3. ProjectID is always synced when reparenting a task (_do_reparent).
   A task's ProjectID must match its parent's ProjectID.

4. Progress is auto-calculated bottom-up:
   leaf task progress = manually set value
   parent task progress = average of direct children (recursive)

5. ProjectStatus sheet is fully auto-computed, never manually edited.

6. Timeline and Table are independent views of the same data.
   Timeline uses get_hierarchy_ordered_tasks() (flat list with level).
   Table uses get_sheet_data() + TaskHierarchyBuilder (nested tree).

7. ExcelWatcher provides live reload — if Excel file is edited externally,
   the UI refreshes automatically after 500ms debounce.

8. DynamicForm is fully generic — it generates fields from any column list.
   Special handling only for known column names (Status, Progress, etc).


================================================================================
KNOWN BUGS / ISSUES (as of last session)
================================================================================

1. add_subtask() reads project_id as values[1] which assumes ProjectID is
   always the second column. If column order changes this breaks silently.
   Fix: use self._display_columns.index("ProjectID") for safe lookup.

2. project_id from Treeview values is a raw string (e.g. "1.0").
   It gets stored directly into data["ProjectID"] without int conversion.
   Can cause mismatches in string comparisons downstream.

3. The canvas overlay progress bar system was removed because it painted
   a solid white canvas over the entire Treeview, hiding all rows.
   Progress now shows as plain numeric text in the Progress column.
